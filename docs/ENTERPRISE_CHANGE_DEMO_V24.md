# CompanyAgent v2.4 · 新云传媒企业价值验证：需求变化 → 提案重算 → 协同交接

> 赛事材料状态：团队参赛页面显示 **2026-11-22 10:23 已提交**。此次只更改 GitHub 项目及自动部署代码，绝不撤回或修改 B1X 上的标题、简介、仓库地址、封面及附件。

## 业务问题

客户经理第一次接到“新品饮料、200 万、公交+地铁”，第二天客户要求“减到100万”或临时改稿。人工流程常需在库存表、媒介价格表、覆盖报告和施工沟通群反复查找。如果只让大模型写一份提案，就无法回答“哪几块媒体变了、预算变动怎么解释、后续哪些岗位受影响”。

## v2.4 实际交互闭环

1. 评委打开公开入口 /judge/，输入**模拟**品牌、业务目标、人群、KPI（这些自由文本只在浏览器显示，不提交到服务器）。
2. 选择媒体类型及 100/200/500 万预算，调用 /judge/api/plan，在仓库自带的80条**虚构**库存上执行与企业后端同一个确定性优化器。
3. 页面自动以100万为基准，调用 /judge/api/workflow，读取**同一源数据**的两次独立优化结果。后端按全部媒体 ID × 媒体类型 × 数量计算新增/减少、净单元差异和实际参考金额差异，既不同比例伸缩，也不编造收益。
4. 展示 9 项技术性提案证据门禁，全部按“已有基本证据/待人工核验”区分。内部标准**不等于赛事官方评分**。
5. 选择“客户改稿/车辆换线/雨天监拍”，复用原有企业 change_workflow 模块生成有责任人和依赖顺序的交接任务。没有实发消息、真实签约、库存锁位。
6. 对常见“商圈覆盖数据缺口”产生一条待审 Skill 候选，明确员工批准前不安装、不赋权、不调用外部工具。
7. 可通过“复制人工复核摘要”复制虚构数据的人审待办；复制文本不发送网络请求。

## 哪些是可验证事实

- 预算从100万到200万：同一优化器+相同虚构数据版本，金额和数量变化可计算；不是真实提效比例。
- 支出与媒体差异：来自优化后全部媒体清单；只截取前12条**展示**，摘要数值按完整清单计算。
- 任务依赖顺序和负责人：复用 enterprise/change_workflow.py；状态为“待人工确认”。
- 数据来源：仓库 data/demo_inventory.csv，附前16位 SHA256 指纹；没有企业权限的真实清单。
- 真实媒体可售、商圈、正式报价、节省的人时、广告收益：**目前没有可核验的真实企业数据或 A/B 证据**，不写成已达成成绩。

## 评委最值得点击的三处

- 把预算从 **200 万 → 500 万**：看选中媒体、单元数量及支出真实重算
- “原预算100万 / 原媒体公交 → 新预算200万 / 新媒体公交+地铁”：看差异计数与责任链
- “车辆换线”：比较客户改稿与车辆换线引起的不同责任岗位；看 Skill 候选为什么需要人工审批

## 企业试点上线的必要条件

红豆公交/地铁 GET 接口：公司正式许可数据用途、真实请求/响应 schema、租户、只读范围、内网网络白名单与密钥托管；可视化暂无已授权 API，仅认可离线导出；配置 PostgreSQL 与多租户访问控制；现场A/B采集从需求到**可审核**提案的人工耗时、重工次数与运营漏项，并经业务负责人签认后才能发布有统计依据的改进报告。
