## 业务范围仅选择一个行业

本轮只针对 **食品饮料**：客户输入品牌、投放时间、100/200/500 万元预算、商圈、公交/地铁媒体偏好，Agent 输出**参考情景方案**与人工待确认问题。当前公开站点只用合成历史样例，不能声称可以预订或锁位。

## 数据接口事实与未知项

- **已提供合同式说明**：红豆媒体管理系统有两个独立的 GET 查询：公交车媒体库存、地铁出入口媒体库存。两者都使用分页和查询起止日期；公交可用 `lineName`，地铁可用 `keyword`；认证需要 `tenant-id` 与 `Authorization: Bearer ...`。
- **尚未提供**：响应 JSON 样例及每个字段定义、错误码与分页总量含义、可售/已锁位区分、账户数据范围、限流约束、企业数据保留规则、可用于试点的脱敏测试账号、网络来源白名单。
- **明确没有 API**：可视化/空间覆盖平台。不得虚构该服务或绕过网页登录抓取。覆盖证据目前只能使用**经授权的离线导出**，按源文件哈希与日期保留，并与库存分开展示。
- **公开代码禁止披露企业服务地址**：公开仓库 `enterprise/hongdou_contract.py` 仅包含不可解析的占位地址和接口请求参数契约；真实主机/路由/租户/令牌只能通过公司审批的私有配置下发。

## 企业人员实际登录与令牌交接（仅批准的私有环境）

根据企业方提供的界面说明，先由获得分配账号的**授权人员本人**登录红豆媒体管理系统并完成验证码。在浏览器打开公交媒体库（也可切换地铁媒体库），在开发者工具 **F12 → Network → Fetch/XHR → 对应库存的 GET `page` 请求 → Headers → Request Headers** 中找到完整的 `Authorization` 值；同一请求显示 `tenant-id: 1`（仅适用于该获授权租户）。

**凭据处理规则：**

- 在企业认可的 Secret Manager / Vault 中创建或更新 `HONGDOU_PRIVATE_BEARER_TOKEN`，支持保存完整 `Bearer <令牌>`，也支持仅保存令牌本体；适配器会恰好添加一次 `Bearer`，不会重复拼接。
- `HONGDOU_PRIVATE_TENANT_ID` 必须与获授权账户和审批范围一致。本次示例的值为 `1`，**不是多租户通用默认值**。
- `HONGDOU_PRIVATE_ORIGIN`、`HONGDOU_PRIVATE_APPROVED_HOST`、`HONGDOU_PRIVATE_BUS_ROUTE`、`HONGDOU_PRIVATE_METRO_ROUTE` 仅允许由企业私有环境负责人配置，通过网络出口白名单精确约束。
- **不要**把 Authorization、Cookie、JSESSIONID、refreshToken、登录密码或截图含敏感字段的内容粘贴到 ChatGPT、GitHub、浏览器分享链接、Railway 公网演示或日志。
- 返回 **HTTP 401** 表明令牌可能过期或无效：由账户持有人重新登录并完成验证码，替换企业私有 Secret Manager 中的令牌，再重新执行经授权的只读查询。不得尝试自动绕过验证码，也不得使用刷新令牌或网页登录 Cookie 在公开服务中冒充业务账户。
- 任何凭据更新都不能代替审批：数据所有者、租户范围、独立 PDP、内网网络出口和受控运行时须先获准，否则适配器仍然拒绝访问。
- 截图展示的是接口地址和请求方式，**没有可复用的完整明文令牌**，因此不能据此认定真实红豆 API 已可调用。

**特别说明：**账号密码、验证码、Token 不会被保存到公开 CompanyAgent 的配置中。F12 的取值过程属于企业内部人工操作；适配器不会自动登录网站，也不会突破验证码保护。

2. **企业内网契约校验（待审批）**：在公司批准的隔离测试环境获取匿名化公交与地铁返回样例，先建立 JSON Schema/字段词典和脱敏工单；查证 HTTP 401/403/429、响应分页、超时、tenant 越权等负向路径。

4. **客户方案比对（待审批）**：可视化覆盖仍使用批准的离线数据；库存和覆盖逐条对齐并标注来源、快照时间、数据冲突。没有覆盖证据时报告未知，不伪造曝光或空车可售。

## v1.8 新增：企业私有网络中的只读请求适配器

新增 `enterprise/hongdou_private_readonly.py`，专门为**未来经审批的企业隔离环境**准备，严禁在当前公网 Railway 运行。它具有以下可测试性质：

- 公交/地铁仅允许两个事先批准的固定 HTTPS GET 路径，限定查询日期 ≤31 天、每页 ≤100、页码 ≤100；用户无法提供任意 URL
- 真实主机、两个 API 路由、`tenant-id` 和 Bearer Token **只从企业私有 Secret Manager / 受控运行时注入**，不出现在 GitHub、Rails 公网环境变量或客服聊天中
- 只允许与企业配置的 exact host 和允许端口匹配；客户端禁用 HTTP 跳转、环境代理继承与自动重试，10s 超时、256 KiB 结果上限；企业网络出口 ACL 仍必须独立配置
- `EnterpriseGrant` 包含数据所有者工单、安全工单、租户范围和过期时间；**仅有工单字符串不算审批**，每次真实读取还必须由外部企业 PDP 回调核验，缺少则默认拒绝
- 当前主项目只支持 `local` 与 `cloud_synthetic` 启动，拒绝 `enterprise_pilot` 生产服务模式；因此**没有可直接开启的企业真实库存 API 端点**
- 仅返回字段名称、列表长度等非业务语义的元信息，**不返回/保存原始库存、客户数据或 Token**；响应未知时 `quantity_semantics_confirmed=false`，不会声称数量真实可售
- 提供 `httpx.MockTransport` 单测覆盖未经审批访问、错误 tenant、过期工单、其他媒体类型、日期/分页越界、301/302 跳转、401/403/429、异常 JSON 和巨型响应

**重要区别：**这是一份**受限客户端代码及契约测试**，没有真实向红豆发起网络请求，也没有证明合同可售、锁位或 2027 年档期。完成真实联调的前提是企业正式批准独立的私有服务部署，提供合法权限下的脱敏返回样例和只读测试 Token；此后才能验证接口的真实 Schema，定义能否用于提案计算的库存字段。

建议企业最小试点链路：

```text
公司 SSO / 租户身份 → PDP 逐次校验授权工单
                            ↓
企业私有服务 / VPC 出站白名单 → 只读公交 / 地铁库存 GET
                            ↓
企业脱敏与校验 → 统一库存字段词典 → 人工核实可售语义
                            ↓
CompanyAgent 私有提案工具（只传审批后的聚合，不发原始数据到外部模型）
```

## 和公网演示严格分离

`deploy/public-demo/` 只运行 `cloud_synthetic` 合成模拟数据，无任何红豆 URL、访问 token、租户 ID、公司网络路由。通过 Caddy HTTPS + 独立访问认证展示客户输入到参考方案；`/api/*`、企业导入/来源同步等高风险入口被拒绝。**这不等于企业生产部署。**
