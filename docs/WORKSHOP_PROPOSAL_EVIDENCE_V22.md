## 9 项非官方门禁（不计算商业 ROI、虚构评委分数）

1. **食品饮料单行业**：与本次赛题约束一致。
2. **Campaign 七要素**：品牌、生意目标、唯一营销目标、人群、日期预算、媒介范围、KPI及核验方式完整；仍待客户确认。
3. **库存来源指纹**：附导入时间、快照指纹、非敏感来源类型；真实可售另查。
4. **预算与媒体约束**：金额一致、不超预算、数量有效、有候选。
5. **100／200／500 万方案**：使用同一冻结快照独立重算。
6. **商圈覆盖证据**：必须来自经许可的离线导出并精确匹配；覆盖不等于可售。
7. **目标日期实时可售**：默认待人工核验，不被历史、虚构数据自动置为通过。
8. **正式报价**：财务/销售确认合同价格、税费、制作施工费和风险条款。
9. **客户确认与运营审批**：无自动锁位、下单、通知客户或替代法务批准。

全部结果始终 **draft_needs_human_review** 或 **blocked**，不把“某几项具备证据”误读为商业可交付。

## 三类自有数据与选择规则

- inventory（必选）：列出当前登录者有权访问的最新快照，记录 id、12 位校验摘要、数量、导入时间和来源类别。
- coverage（可选）：可视化平台不支持 API；只能人工导入批准的 CSV/XLSX。若显式选择后快照不存在/越权，则返回 HTTP 403 并拒绝退化。
- pricing（可选）：刊例表/参考价格可另外导入；若显式选择的快照不存在/越权，同样拒绝静默回退为其他刊例。

快照来源类别 `synthetic_demo / historical_reference / uploaded_unverified / other_unverified / missing`；上传成功**不代表真实商业字段已验证**。数据来源 ID、hash 和时间戳附于 Run，API 不返回原始 Token、企业内网 URL 或库存行。

## API

- `GET /enterprise/api/workshop/data-readiness`: 获取授权范围内的无敏感内容快照元数据、红豆与可视化能力边界。
- `GET /enterprise/api/runs/{id}/workshop-readiness`: 从冻结 Run 返回内部提案自查，不改任何资源、不调外部网络。
- `POST /enterprise/api/runs`: 在已有参数上新增 `pricing_dataset_id`，与 `inventory_dataset_id/coverage_dataset_id` 一起决定被冻结的数据快照。

所有接口要求应用会话登录；Run 检查仍按 owner / admin 权限，跨用户访问返回 404。写入运行要求 CSRF。公开 Railway 是 synthetic-only：不保存真实 Token、Cookie、合同或企业库存。

## 红豆令牌与内网试点边界

员工在公司授权系统通过验证码登录后，如企业审批允许，在内网秘密管理器存放短期 Bearer Token；严格限定租户（会议示例 tenant-id: 1 **只对应被批准的账户**）、主机、bus/metro GET 路径、期限。OAuth2 也必须遵守供应商正式授权的认证流程，绝不将账户密码加入公开仓库/Prompt/浏览器。此工作台没有连接真实红豆，也不认定 API 返回字段含义已经明确。

## 人工验收

1. 在客户首页选择合成库存快照，生成一个七要素完整的食品饮料投放情景。
2. 查看 9 项门禁：模拟库存可以有指纹和预算合格，但覆盖、可售、报价、审批不可自动通过。
3. 指定一个根本不存在的覆盖/刊例快照，API 应拒绝而不是静默退化。
4. 新建私有账户，尝试读取别人的 Run/不可访问快照，必须拒绝。
5. 公开演示上线后检查没有开启红豆真实访问或擅自启用可视化 API。
6. 不声称正式提交到 B1X，直到现场点击「提交作品」并核验状态。
